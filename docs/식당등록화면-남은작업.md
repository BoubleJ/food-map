# 식당 등록 화면 남은 작업

admin `/restaurants/new` 에서 아직 구현하지 않은 내용이다. 디자인은 claude.ai 의 "식당 등록 화면" 캔버스를 따른다.

## 지금 상태

- 목록 상태는 연결되어 있다. 검색, 선택, 목록에서 빼기, hover, 지도 이동, 지도 축소 시 점 마커, 더 보기가 동작한다
- 하단 "등록" 클릭 시 `?panel=form` 으로 이동하지만, 등록 폼 대신 "목록으로" 버튼만 있는 임시 화면을 그린다
- API hook(`useLookupAddressesMutation`, `useRegisterRestaurantsMutation`)과 선택 상태 reducer(`useRestaurantSelection`)는 만들어 두었다

## 등록 폼

### 폼 상태

- `routes/restaurants/-hooks/restaurantRegisterForm.ts` 에 폼 값 타입, `restaurantRegisterFormSchema`, `@mantine/form` 의 `createFormContext` 를 둔다
- 폼 값은 `categories`, `isVisible`, 카카오 장소 ID 를 키로 하는 `restaurants`(설명, 가맹점 이름)로 둔다. 식당을 선택에서 빼도 폼 값을 지우지 않고, 등록 요청을 만들 때 선택한 식당 기준으로 꺼낸다
- `useForm` 은 `RestaurantRegisterContent` 에서 만들어 "목록으로" 클릭 후 돌아와도 입력값이 남게 한다
- 카테고리는 1개 이상, 설명은 500자까지 받는다. 설명과 가맹점 이름이 비어 있으면 등록 요청에 넣지 않는다

### 컴포넌트

- `RestaurantRegisterForm`: 등록 폼 패널. "목록으로" 버튼, "N개 식당 등록" 제목, 카테고리와 "지도에 노출" 입력, "주소 조회 (N곳)" 버튼, 식당 카드 목록(children), 하단 안내와 등록 버튼을 그린다
- `RestaurantRegisterFormItem`: 식당 카드. 이름, "주소 확인됨" 또는 "주소 미확인" 배지, 주소, 거리 경고, 설명과 가맹점 이름 입력, X 버튼을 그린다
- `-utils` 의 `getDistanceMeters`: 카카오 좌표와 주소 조회 좌표 사이 거리를 m 단위로 계산한다. 단위 테스트를 함께 둔다

### 동작

- "주소 조회 (N곳)" 클릭 시 주소를 확인하지 않은 식당만 조회한다. `found` 는 `confirmAddresses` 로 저장하고, `notFound` 는 `deselect` 로 선택에서 빼고 식당 이름을 담아 알린다
- 카카오 위치와 100m 넘게 차이 나면 카드에 경고를 그리고 등록은 막지 않는다
- 모든 식당의 주소를 확인해야 등록 버튼을 누를 수 있다. 확인하지 않은 식당이 있으면 "주소를 확인하지 않은 식당이 N곳 있습니다" 를 그린다
- 등록 201 응답 시 `clear` 로 선택과 주소를 비우고, 폼을 초기화하고, `panel` 을 지워 목록으로 돌아간다
- 등록 409 응답 시 이미 등록된 식당을 `deselect` 로 빼고 폼 상태를 유지한다
- 카드 X 클릭 시 `deselect` 로 선택에서 뺀다. 마지막 식당을 빼면 `panel` 을 지우고 목록으로 돌아간다

## 등록 폼 상태의 지도

- `RestaurantRegisterFormMarkers` 로 선택한 식당의 카카오 위치(파란 말풍선), 주소 조회 위치(`PlaceMarker` 의 `address` variant 점), 두 위치를 잇는 점선(`Polyline`), 거리를 그린다
- 등록할 때 저장하는 좌표는 주소 조회 좌표라서, 관리자가 두 위치를 지도에서 비교하고 등록할지 판단하는 데 쓴다
- 거리 경고만으로 충분하다고 판단하면 만들지 않고 목록 마커를 그대로 그린다. 아직 정하지 않았다
- `RestaurantRegisterContent` 가 `isFormOpen` 에 따라 지도 children 을 `RestaurantCandidateMarkers` 와 바꾼다. 등록 폼으로 넘어가면 선택한 식당이 모두 보이도록 지도 범위를 맞춘다

## 테스트

- admin 에 컴포넌트 테스트 설정(vitest jsdom 환경)이 없다. 지금은 순수 함수인 reducer 테스트만 있다
- 설정을 추가한 뒤 목록 상태와 등록 폼 상태의 단위 테스트와 e2e 를 작성한다. 프로젝트의 `page-test` skill 로 사용자 흐름 기준 테스트를 만들 수 있다

## 확인할 것

- `KakaoMap` 이 `key={keyword}` 인 `RestaurantRegisterContent` 안에 있어서 검색어가 바뀔 때마다 지도를 새로 만든다. 화면이 깜빡이면 지도를 `key` 밖으로 뺀다
- 주소 조회 503 응답 알림은 "주소 조회에 실패했습니다" 와 서버 메시지("주소 조회 요청이 많습니다. 잠시 후 다시 시도해 주세요.")를 그린다. 캔버스의 "주소 좌표 조회가 지연되고 있습니다" 문구는 아직 고치지 않았다
- 이 지역 재검색과 API 에러 전역 처리는 `docs/검토사항.md` 에 적어 두었다
