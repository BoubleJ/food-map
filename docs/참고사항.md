# 참고사항

## admin 인증

- admin API 인증 로직을 추가해야 한다
- `infra/caddy/Caddyfile` 이 `{$DOMAIN}/api/*` 와 `api.{$DOMAIN}` 도 api 로 연결해서, 사용자용 도메인에서도 `/api/admin/*` 를 호출할 수 있다

## 에러 처리

- [neverthrow](https://github.com/supermacro/neverthrow) 를 쓰면 예외를 던지지 않고 `Result` 값으로 함수형 에러 처리를 할 수 있다
- NestJS, oRPC 와 함께 쓰는 사례: [teable](https://github.com/teableio/teable), [modular-monolith-starter](https://github.com/ihssmaheel-dev/modular-monolith-starter), [hazard-pay](https://github.com/arnavp103/hazard-pay)(oRPC 만)

## 식당 등록 화면의 이 지역 재검색

- 식당 등록 화면 디자인에는 지도에 보이는 영역에서 같은 검색어로 다시 검색하는 "이 지역 재검색" 버튼이 있지만 지금은 구현하지 않았다
- 카카오 키워드 검색은 영역마다 45곳까지만 주고, 전국 검색은 영역을 4단계까지 나눠도 서울처럼 장소가 많은 영역에서 일부 지점을 받지 못한다. 등록할 지점이 검색되지 않는 경우가 생기면 구현한다
- 구현하려면 restaurant-search contract 에 지도 영역(`rect`) 입력을 추가하고, 영역이 있으면 `PlaceSearchService` 가 전국 대신 그 영역부터 검색하게 한다

## admin API 에러의 전역 처리

- 지금은 mutation hook 마다 `onError` 에서 에러 알림을 띄운다
- 500 처럼 화면 상태와 관계없는 에러는 `main.tsx` 의 `QueryClient` 에 `new MutationCache({ onError })` 를 설정해 한 곳에서 알림을 띄울 수 있다. 알림 제목이 API 마다 다르면 `mutationOptions` 의 `meta` 에 제목을 넣고 전역 `onError` 가 읽게 한다
- 409 처럼 화면 상태를 바꿔야 하는 에러는 hook 에서 처리한다
