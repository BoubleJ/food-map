# 식당 등록 기획

2026-10-02 논의한 admin 식당 등록 화면과 API 기획이다. 아직 작업하지 않았다.

## 화면

- 상단에 식당명 검색 input, 아래에 카카오맵(화면 너비 2/3)과 우측 패널을 둔다
- 지도는 검색 결과 마커가 모두 들어오는 범위로 맞춘다. +/- 확대 버튼은 넣지 않는다
- 마커는 `react-kakao-maps-sdk` 의 `CustomOverlayMap` 으로 그린다
- 우측 패널은 목록 상태와 등록 폼 상태를 오간다

### 목록 상태

- 항목마다 식당명, `categoryName`, 도로명 주소, 카카오맵 링크, 체크박스, X 버튼을 그린다
- 항목 hover 시 해당 마커가 CSS 애니메이션으로 움직이고 맨 위로 올라온다
- 항목 클릭 시 해당 마커 위치로 지도를 이동하고 확대한다
- 등록된 식당(`isRegistered`)은 "등록됨"으로 표시하고 체크박스를 그리지 않는다
- X 버튼 클릭 시 목록과 지도에서 빠진다. 화면 상태에서만 빠지고 새 검색어로 검색하면 다시 나온다
- 이름에 검색어가 들어간 다른 가게도 나온다. 백엔드에서 거르지 않고 관리자가 X 버튼으로 뺀다
- 하단 "더 보기" 클릭 시 다음 페이지를 붙인다. `isEnd` 가 `true` 면 버튼을 그리지 않는다
- 여러 식당을 체크하고 "등록" 클릭 시 등록 폼 상태로 바뀐다

### 등록 폼 상태

- 공통 입력: `categories`(필수), `isVisible`(기본값 `true`)
- 식당마다 입력: `description`(선택)
- 식당별 X 버튼 클릭 시 선택에서 빠진다
- "목록으로" 클릭 시 검색 결과를 유지한 채 목록으로 돌아간다
- 등록 성공 시 알림 후 목록으로 돌아가고, 등록한 식당을 다시 요청하지 않고 "등록됨"으로 바꾼다
- 등록 요청 중에는 등록 버튼을 비활성화한다

### categories 입력

- 검색할 수 있는 다중 선택 input(Mantine `Combobox` + `PillsInput`)
- 일치하는 카테고리가 없으면 "+ 추가" 항목을 보여주고, 클릭 시 영문 코드를 입력받아 새 카테고리를 만든다

## API

### 검색 `GET /admin/restaurant-search`

- 입력에 `page`(1~3)를 추가한다. 카카오는 `size` 최대 15, 검색어 하나당 최대 45개를 준다
- 응답을 `{ restaurants, isEnd }` 로 바꾼다. `isEnd` 는 카카오 `meta.is_end` 값이다
- juso 주소를 찾지 못한 식당은 응답에서 뺀다
- 지도 범위(`rect`)로 검색 범위를 좁히지 않는다

### 등록 `POST /admin/restaurants`

- 여러 식당을 한 번에 받는다. `{ common: { categories, isVisible }, restaurants: [{ kakaoPlaceId, name, placeUrl, 주소, description }] }`
- 한 트랜잭션에서 저장하고, 이미 등록된 식당이 있으면 409 로 응답하고 아무것도 저장하지 않는다
- `thumbnailUrl`, 영업시간은 받지 않는다. `isInBusiness` 는 `true` 로 저장한다

## 스키마

- 카테고리를 enum 배열에서 `categories` 테이블(id, 영문 코드, 한글 이름)과 `restaurant_categories` 연결 테이블로 옮긴다
- `RESTAURANT_CATEGORIES`, `no-restaurant-value-union` 규칙을 지운다

## 환경변수

- `VITE_KAKAO_JS_KEY` 를 루트 `.env.local` 에서 관리하고 admin, web 의 `vite.config.ts` 에 `envDir: "../.."` 를 추가한다
- 카카오 디벨로퍼스에 admin 도메인(`http://localhost:3001`, 배포 도메인)을 등록해야 한다

## 정하지 않은 내용

- `docs/음식점-검색-502.md` 의 수정 방향과 맞추기
  - 검색에서 좌표를 조회하지 않으면 마커 좌표로 카카오 `x`, `y` 를 화면 표시용으로만 응답에 추가한다
  - 등록 개수 제한(문서는 최대 10개)과 저장 시 좌표를 찾지 못한 경우의 응답
- 카테고리 영문 코드 규칙(`^[a-z]+$`, unique)을 강제할지
- 스키마 변경을 `feature/db` 와 `feature/api` 중 어느 브랜치에서 할지
- 배포 빌드에 `VITE_KAKAO_JS_KEY` 를 넘기는 설정(`deploy.yml` build-args, Dockerfile `ARG`)을 이번에 할지
