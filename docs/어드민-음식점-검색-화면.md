# 어드민 음식점 검색 화면

admin 에 oRPC client(`apps/admin/src/utils/orpc.ts`)와 `react-error-boundary` 를 추가했고, 검색 화면은 아직 만들지 않았다. 화면 구성과 API 변경은 `docs/식당-등록-기획.md` 를 따르고, 이 문서에는 검색 결과를 조회하고 에러를 처리하는 방법만 적는다.

## 정할 것

- 검색 화면 경로. `/` 를 쓸지 `/restaurants/new` 같은 경로를 새로 만들지
- 검색어를 컴포넌트 state 로 둘지, url 쿼리스트링(`?keyword=`)으로 두고 라우트 `loader` 에서 `queryClient.ensureQueryData` 로 미리 조회할지

## 구현 방향

- `useSuspenseQuery(orpc.admin.restaurantSearch.queryOptions({ input: { keyword } }))` 를 감싼 `useGetRestaurantSearch` 훅을 만든다. `data` 타입은 contract 의 output 스키마에서 추론되고 `undefined` 가 빠진다
- `useSuspenseQuery` 는 `enabled` 를 받지 않고 `skipToken` 도 런타임에서 지원하지 않는다. `skipToken` 은 타입 에러가 나지 않으니 주의한다. 검색어가 비어 있으면 결과 컴포넌트를 렌더링하지 않는다
- 결과 컴포넌트는 `QueryErrorResetBoundary` > `ErrorBoundary` > `Suspense` 순서로 감싼다
- 검색어가 바뀔 때 이전 결과를 유지하려면 `useDeferredValue` 나 `startTransition` 을 쓴다

## 에러 응답

임시 테스트에서 `OpenAPILink` client 로 호출해 확인한 형태다.

| 응답                       | `ORPCError`        | 화면 문구를 읽을 위치                        |
| -------------------------- | ------------------ | -------------------------------------------- |
| 400 (빈 검색어, 41자 이상) | `code=BAD_REQUEST` | `error.data.issues` (contract zod 검증 결과) |
| 502 (행정안전부 API 오류)  | `code=BAD_GATEWAY` | `error.data.body.message` (Nest 예외 형식)   |

502 응답은 `RethrowHandlerPlugin` 때문에 oRPC 에러 형식이 아니고 Nest 예외 형식(`{ statusCode, message }`)으로 온다.

## 확인하지 못한 것

- 브라우저에서 `localhost:3001/api` 요청이 Vite proxy 를 거쳐 api 로 가는지. 개발서버를 띄워 확인해야 한다
